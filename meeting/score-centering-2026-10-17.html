今天围绕一个明确问题展开：rollout 引擎与训练引擎计算的概率存在差异时，这种差异怎样进入策略梯度，以及 Score Centering 如何估计并扣除由此产生的期望 score 漂移。随后重点讲 top-k/tail 近似和 AReaL 的工程链路。

背景02 / 13

一次 RL 训练迭代，发生了什么？

先生成样本，再评价行为，最后用 reward 更新生成策略。

1 Prompt输入问题、上下文、任务约束
2 RolloutvLLM 生成回答，行为分布 q
3 Reward规则、执行器或奖励模型
4 Advantage衡量回答相对表现
5 UpdateFSDP 计算梯度，更新策略 pθ
推理阶段 Rollout

回答是怎样生成的

系统按当前推理引擎实际使用的分布逐 token 采样。重点是生成吞吐、延迟、KV cache 和批处理效率。

更新阶段 Training

回答是怎样变成梯度的

训练引擎重新计算模型概率，用 advantage 构造 loss，再通过反向传播与优化器更新参数。

问题入口：生成样本来自 rollout 侧分布，梯度却通过训练侧模型计算。两边概率是否一致，会影响优化目标。

讲者备注 · 训练流程

以 SQL 生成举例：prompt 包含自然语言需求和数据库 schema，模型生成 SQL，执行器返回是否正确的 reward。GRPO 通常会在同一个 prompt 下采样多条回答，再根据组内 reward 形成相对 advantage。注意推理和训练通常由不同系统执行，即使共享权重，概率计算也可能存在偏差。

失配03 / 13

同一组权重，概率也可能不同

TIM（Training-Inference Mismatch）是 rollout 行为分布与训练端概率计算之间的不一致。

数值路径

数值路径差异

BF16 / FP8、量化、矩阵乘法内核、softmax 实现等，让同一模型得到略有差异的 logits 或 log-prob。

策略与采样

策略与采样差异

权重版本不同、异步 rollout、温度、top-p、top-k 或 logits processor 改变实际行为分布。

实际系统中，这两类因素可能同时存在，应通过固定权重与固定样本分别测量。

下一个 token 的概率（示意）

示意数据：训练侧 p=(0.6, 0.4)，rollout 侧 q=(0.7, 0.3)。差异看起来很小，却会改变训练样本的统计分布。

讲者备注 · 两类 mismatch

讨论问题时需要把数值路径差异和真实策略差异分开。相同权重时固定同一批 token 重算两侧 logprob，测量的主要是数值路径差异；让 rollout 使用旧版本权重则会叠加 policy staleness。采样规则也是实际行为分布的一部分，不能把原始模型 softmax 自动当成真实采样概率。

策略梯度基础04 / 13

Reward 怎样影响模型参数？

Log-probability
log pθ(y | s)

给定前缀 s，模型生成 token y 的概率取对数。整段回答的 log-prob 是每个 token 条件 log-prob 的求和。

Advantage
A > 0　A < 0

正 advantage 推动提高该行为的概率；负 advantage 推动降低它。GRPO 常从同一 prompt 下多条回答的相对 reward 得到 advantage。

Importance ratio
r = pθ(y|s)q(y|s)

衡量当前训练策略给该 token 的概率，相对 rollout 行为分布发生了多大变化。

ℓ = −A · log pθ(y | s)

最基本的策略梯度目标。PPO 在其基础上使用 ratio 和 clipping，限制单次策略更新幅度。

AReaL 配置提示：use_same_logprob 会改变 PPO loss 中旧策略 log-prob 的来源；它不能保证训练侧的梯度计算路径与 rollout 侧完全一致。

讲者备注 · 三个概念

如果某条回答表现好，advantage 为正，优化器会推动相关 token 的 logprob 上升；反之则降低。PPO ratio 比较训练端当前概率和样本生成时的旧策略概率，clipping 用来限制一次更新过大。复用 rollout 的 old_logprob 可以确保 PPO 分母使用 rollout 记录值，但训练侧梯度仍由 trainer 模型计算，二者的数值路径差异依然可能存在。

漂移从哪里来05 / 13

关键恒等式：on-policy 时，期望 score 为零

Score function 衡量参数微小变化时，某个 token 的 log-probability 会如何变化。

sθ(a | s) = ∇θ log pθ(a | s)

当 token 确实从同一个训练策略 pθ 中采样时，对所有 token 的 score 按各自概率求平均，结果必然为零。

推导
Ep[sθ] = Σa pθ(a) ∇θ log pθ(a)
定义
    = Σa ∇θ pθ(a)
∇log p = ∇p / p
    = ∇θ Σa pθ(a) = ∇θ 1 = 0
Σ p = 1

最后一步来自概率归一化：所有可能 token 的概率总和恒等于 1，对参数求导后结果为 0。

样本来自 pθ

Ep[sθ] = 0

策略与采样分布一致，没有这类平均 score 漂移。

样本来自 q，且 q 与 pθ 不同

Eq[sθ] ≠ 0

可能出现系统性 drift。

讲者备注 · 推导直觉

这个恒等式是全场最关键的数学起点。p(a) 乘上 log p(a) 的梯度，可以改写成 p(a) 的梯度；所有 token 加起来，就是对概率总和求导。因为总和等于 1，所以结果为零。换成 q 分布对 p 的 score 加权时，就不再有这个保证。

梯度分解06 / 13

分布不一致会给梯度增加一个偏移项

Eq[A sθ]
=
Covq(A, sθ)
+
Eq[A] · Eq[sθ]
有效学习信号
TIM 漂移
Covariance 是有效信号。它反映 advantage 与 score 的关联：表现更好的行为，是否对应应当增加的 token 概率。
期望漂移是偏移项。由 advantage 均值与 rollout 分布下的平均 score 相乘而成。它可能推动参数更新，却不代表 reward 与行为之间的有效关联。

TIM 是 reward collapse 的一种候选机制。奖励稀疏、全零 advantage、异步策略陈旧性与蒸馏 loss 也可能参与其中。

讲者备注 · 公式拆开讲

把策略梯度写成协方差和均值乘积，就能将学习信号与漂移分开。前一项表示 advantage 与 score 是否相关；后一项来自期望 score 不为零。如果样本分布不匹配，后一项即使与 reward 区分无关也可能存在。它能解释一些训练不稳定现象，但单独观察 reward 坍塌还不能证明一定是它造成的。

Score Centering07 / 13

SC：估计平均 score，再从目标中扣除

s̃θ(a | s) = sθ(a | s) − Ea′~q[sθ(a′ | s)]
1

计算训练 score

对当前生成位置的候选 token，计算 trainer 的 log-probability 及其梯度。

2

估计期望 score

使用 rollout 侧概率给不同 token 加权，估计采样分布下的平均 score。

3

减去漂移项

在策略目标中加入 correction，让其梯度抵消期望 score 的偏移。

理想化结果
gSC = Eq[A · s̃θ] = Covq(A, sθ)

扣除 Eq[A] · Eq[sθ] 这部分漂移，保留 advantage 与 score 的协方差项。

正确性检查：当 p=q 时，期望 score 为零，SC 应退化为原始策略梯度，校正项及其梯度应为零。

讲者备注 · 为什么叫 centering

它可以类比统计中的中心化：先找出整体平均偏移，再从每条观测中减去。这里处理的是向量形式的 score，而不是普通的一维数据。用 loss 实现时，需要让 correction 项的梯度抵消期望 score，并保持它与 advantage 和所用重要性权重之间的关系。

Top-k 与 tail 近似08 / 13

用 top-k 头部估计整张词表

全词表可能有数万 token。传递所有 token 的概率很贵，SC 只传概率最高的 k 个候选，再估计 tail 的总质量。

k = 128（本次实现默认值）

第一步：先算两侧头部质量
qH = Σv∈H qv　pH = Σv∈H pv

得到 tail 的剩余质量：qtail = 1 − qH，ptail = 1 − pH。

第二步：用比例系数匹配 tail 总量
ρ = 1 − qH1 − pH

近似令 tail 内部 qv ≈ ρ pv，用一个比例调整 tail 的总质量。

例：qH=0.92、pH=0.90，则 tail 分别剩余 0.08 和 0.10，ρ≈0.8。

讲者备注 · 为什么是 top-k

头部候选往往覆盖了大部分概率质量，但仍保留一定的 tail。两个分布对相同 top-k 集合的概率质量可以直接计算；tail 的总量由归一化性质得到。近似假设 tail 形状与 trainer 分布相似，整体按 rho 缩放。它不是逐个恢复所有 tail token 的真实概率，而是用低成本近似期望 score。

校正项09 / 13

把头部的概率残差变成加性校正

纯 Score Centering
C(s) = Σv∈H sg(qv − ρ pv) · log pv

每个头部 token 都有一个残差：rollout 给它的概率，与按 tail 比例缩放后的 trainer 概率之差。残差作为固定系数，乘上训练侧 log-probability，形成 correction。

stop-gradient（sg）：校正系数在反向传播时固定，梯度仅通过 trainer 的 log-probability 传递。
加权变体：和 TIS / MIS 的组合
rv = pv / qv
TIS 上界截断f(r) = min(r, upper)
MIS 区间屏蔽仅保留 low ≤ r ≤ high
wv = f(pv / qv)
α = ρ · f(1/ρ)
C(s) = ΣH sg(qvwv − α pv) log pv

完整策略目标还包含实际采样 token 的加权策略项；correction 与 advantage 一起进入目标，并按 loss mask 和有效 token 数进行归一化。

讲者备注 · 如何理解残差

在纯 SC 模式下，头部权重为 1，tail 比例由 rho 决定，因此残差为 qv-rho pv。需要截断或屏蔽重要性权重时，使用 f(r) 构造头部与 tail 权重。策略项与 correction 需要使用一致的目标定义；实际配置的上下界会决定 TIS/MIS 的有效行为。

显存优化11 / 13

分块 autograd：不物化完整的 FP32 softmax

训练侧已经有完整 logits。计算 SC 只需要 top-k 对应的 log-probability；保存完整的 log-softmax 中间张量会额外消耗显存。

[chunk, vocab] × blocks分块计算归一化项，只输出需要的候选 token log-prob。

讲者备注 · 显存管理

自定义 autograd 函数将 logits reshape 为 [N,V]，每次只处理有限数量的位置。前向保存 logits、token IDs、每行最大值与归一化分母；反向重新计算当前 chunk 的 softmax，再计算 log-softmax 的梯度。额外 FP32 工作区从 [N,V] 降到 [chunk_size,V]。目前 Ulysses SP 因本地 logits 与 all-gather 后的 loss 数据长度不一致而被显式限制；多轮 concat 也有相应约束。
