# AReaL 社区周会纪要（2026-10-31）

[English](README.md) | 简体中文

本纪要记录会议当日的讨论、结论与行动事项。文中的进展、验证结果及时间安排均以会议日期为准。

## 一、关键结论与进展

### 1. VRM 优化与问题修复

- **Vision Tower 冻结与缓存刷新**：RL 训练更新 Vision Tower 参数后，SGLang 推理侧复用旧的 embedding
  cache，会导致训练与推理的对数概率差异（log p diff）发生漂移。会议确定了两种处理方式：在 RL 训练期间冻结 Vision Tower 权重，或在 S 阶段
  plug-in 时刷新缓存。
- **图像压缩一致性**：已修复训练侧 Hugging Face processor 与推理侧 SGLang
  图像处理逻辑不一致的问题，例如大块图像的压缩比例差异。通过环境变量 `AREAL_VRM_ALIGN_SGLANG`（默认为 `true`），使训练侧采用与 SGLang
  一致的图像压缩逻辑，减小训推差异。
- **FSDP 性能基准测试工具**：已提供 FSDP 训练后端的 Benchmark 工具，并附有 README 和使用教程，用于单卡性能评估与压测。

### 2. 标准化 Benchmark 计划

社区计划参考 vLLM 社区的标准化实践，推出统一的 Benchmark 方法和数据集，覆盖 IR/VR、Agent 等场景，用于评估 AReaL 的性能及 PR
合入带来的性能变化。团队目前正在开展内部验证，以确保评估结果无偏。

### 3. Score Centering 支持

AReaL 已支持 Score Centering，可配合 SGLang 和 FSDP 后端使用，以缓解训推差异的影响。会上分享的数据显示，训练准确率有所提升。

**使用限制：Score Centering 与拒绝采样（Rejection Sampling）不能同时使用。**

### 4. 硬件生态扩展

- **AMD GPU**：已实现端到端运行。贡献者提供了 Dockerfile，相关问题修复 PR 已合入主仓。
- **Intel XPU**：初步支持的 PR 已合入主仓。目前仅完成小规模实验，尚未进行大规模验证。
- **CI 策略**：AMD 和 Intel 的支持代码直接合入主仓。通过 NVIDIA GPU CI 测试仍是合入的前提；未通过的改动暂不合入。

### 5. FP8 训练支持

- **当前进展**：支持 Qwen2.5 Dense 模型 FP8 训练的 PR 已提交，处于初步验证阶段。支持两种配置：BF16 训练 + FP8 推理，以及 FP8 训练
  \+ FP8 推理。
- **推荐配置**：实测发现，FP8 训练 + FP8 推理的训推差异漂移较为严重。目前更推荐 **BF16 训练 + FP8 推理**，以兼顾性能提升与精度稳定性。
- **后续计划**：预计下周合入该 PR，供社区使用和验证；随后探索 MoE 模型中适合 FP8 量化的部分。

### 6. 训推策略版本差控制

针对异步训练中慢数据（长尾数据）导致策略版本差过大的问题，新增了两项控制机制：

- **推理侧**：在采样过程中丢弃过期数据。
- **Actor 侧**：对过旧的 token 进行掩码处理，使其不参与损失计算。

上述机制用于控制数据的策略版本滞后，提升训练稳定性。相关 PR 待审核后合入。

### 7. AReaL Autopilot 分享（李文爽）

- **目标**：减少模型适配与部署中的人工介入，实现全生命周期自动化。
- **Kernel Evolution**：利用 Agent 自动搜索和演化高效且满足数值一致性要求的 Unified Kernel。在 H20
  上的实测结果显示，端到端吞吐提升约 10%，Attention 测试用例获得 2–5 倍加速。
- **Elastic Training**：通过微服务架构解耦组件，根据工作负载动态分配或释放 Actor 资源。Demo 已验证 Actor 从 0 卡到 4
  卡的动态切换；仿真结果显示约 10%–20% 的提升，真实工作负载下的测试尚待开展。

## 三、待确认事项与讨论

### 1. 昇腾 NPU 的 FP8 支持

李家乐询问 Yong，昇腾 NPU 是否已稳定支持 FP8 训练与推理。Yong 表示，目前仅在 Ascend
910B（A5）分支上开展了初步实验，功能已跑通，但受限于硬件资源，尚未完成充分验证。

### 2. 多硬件 CI 测试策略

Yong 提出，主仓改动可能导致非 NVIDIA 硬件（如 NPU）的 CI 失败。李家乐确认，AMD 和 Intel 的支持代码已合入主仓，但 NVIDIA GPU CI
仍是合入检查的必要条件。NPU 的底层实现（Macron/MindSpeed）与主仓存在差异，兼容性仍需持续观察和验证。

### 3. Autopilot 与 Benchmark 联动

李家乐指出，Autopilot 动态调整的效果仍缺少统一的最终评价标准，建议与正在建设的 Benchmark 体系结合，使 Autopilot 能够通过 Benchmark
自我检验和优化。袁彬航对此表示认同，认为这是提升 RSI 链路能力的一环。
